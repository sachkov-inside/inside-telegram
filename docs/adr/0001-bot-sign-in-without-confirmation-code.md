# Подтверждение входа в боте без сверки кода

Вход через Telegram-бота завершается одной кнопкой «Подтвердить вход». Бот не показывает
шестизначный `confirmationCode` и не просит сверить его с кодом в браузере. Код остаётся в
контракте `inside.bot-sign-in.v1` для совместимости, но в пользовательском пути не участвует
([спецификация](../specifications/bot-sign-in-v1.md)). Владелец выбрал этот путь 2026-09-06 ради
простого входа и подтвердил его 2026-09-24 после проверки безопасности
([#80](https://github.com/sachkov-inside/inside-telegram/issues/80)).

## Принятый риск

Без сверки кода человек не может убедиться в боте, что подтверждает именно тот вход, который сам
начал на сайте. Остаточный риск — подтверждение входа, начатого не им. Владелец принимает этот риск
для текущего этапа: цена лишнего шага для каждого входа сейчас выше, чем ожидаемый ущерб. Подробная
оценка находится в закрытом отчёте проверки безопасности 2026-09-24 и в публичные документы не
выносится.

Риск ограничивают свойства, которые остаются обязательными:

- запрос входа живёт не больше пяти минут, решение после истечения не принимается;
- кандидат закрепляется первым личным `/start`; решение принимается только из того же личного чата;
- доказательство выдаётся один раз и только доверенному серверу, который знает секрет браузера;
- отдельный `TELEGRAM_SIGN_IN_INTEGRATION_SECRET` и проверка webhook secret от 32 символов не дают
  подделать решение в обход Telegram.

## Когда пересмотреть

Решение пересматривается, и сверка кода или предупреждение в сообщении бота возвращаются в
обсуждение с владельцем, если выполняется любое из условий:

- поступил сигнал о входе, который человек не начинал, или о попытке выманить подтверждение;
- вход только через Telegram даёт Account права автора, администратора или платёжные действия;
- ссылки входа начинают массово распространяться вне сайта, например в рассылках или рекламе;
- Platform или Logto добавляют второй фактор или повышение уровня входа для чувствительных действий.
