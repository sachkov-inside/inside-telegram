# Отчёт агента

Отчёт — один самостоятельный файл
`<основной каталог проекта>/.reports/<задача>/<дата>-<имя>.md`. Владелец открывает его как файл.
Краткий итог по-прежнему идёт в PR.

Когда отчёт обязателен и какие команды считаются проверкой, говорит правило pipeline проекта.
Общее условие: отчёт пишется, когда работа сдаётся владельцу.

## Шаги

1. Создай файл с фактами из git и tracker:

   ```bash
   python3 <каталог skill>/report.py new --task <номер|ссылка|строка> --name <короткое-имя>
   ```

   Команда печатает путь файла. Шапку (задача, ветка, worktree, PR, сессия) она пишет сама.
   Работал в другом worktree — передай `--worktree <путь>`. Нужна диаграмма — добавь `--html`.
   Проект без tracker передаёт задачу строкой.
2. Собери факты: `git log` и `git diff` ветки, состояние задачи и PR, вывод проверок проекта.
   Не пиши по памяти то, что можно получить командой.
3. Заполни разделы по таблице ниже и строку `Статус:`. Другие PR задачи допиши в строку `PR:`.
4. Сдай отчёт:

   ```bash
   python3 <каталог skill>/report.py finish <файл>
   ```

   Ошибка — исправь и запусти снова. Пока `finish` не вернул 0, отчёт не сдан: не называй работу
   сданной. `finish` ставит строку `Сдан:` со временем сдачи.
5. Напечатай владельцу путь из вывода `finish` и одну строку итога.

## Разделы

| Раздел | Что писать |
|---|---|
| `Статус:` в шапке | `готово`, `остановлено` или `ждёт приёмки` |
| `## Что сделано` | от одной до пяти строк простыми словами: кто что сделал |
| `## Что нужно от владельца` | решение, вход, gate; ничего — «Нет.» |
| `## Проверка` | три подраздела: `Проверено командой`, `Проверить владельцу`, `Не проверено` |
| `## Решения` | развилки, которые агент решил сам, и почему; не было — «Нет.» |
| `## Что дальше` | следующий шаг; поручение агенту пиши полностью, чтобы его можно было скопировать |

Правила:

- Одна мысль на строку. Числа, имена и пути вместо «некоторые» и «ряд».
- Каждый пункт `Проверено командой` называет команду в `` ` `` или ссылку на CI. Не выполнял
  команду — пункт идёт в `Не проверено`.
- Необратимое действие (merge, удаление, публикация) в `Что дальше` помечай словом «необратимо».
- Задача дала несколько PR — все они идут в строку `PR:`, в порядке merge.

## Когда HTML

Markdown хватает в большинстве задач. HTML (`new --html`) нужен только для диаграммы: поток,
структура, «было и стало». Видео и интерактивную страницу не делай без названной причины.

- Файл самостоятельный: стили и inline SVG внутри, внешних скриптов и картинок нет.
- Учитывай светлую и тёмную тему: `@media (prefers-color-scheme: dark)`.
- Разделы — заголовки `<h2>`, подразделы проверки — `<h3>`, пункты — `<li>`.

Как выбрать вид (из skill `pr` Matt Pocock): логика — псевдокод; поток вызовов — дерево вызовов;
раскладка файлов — короткое дерево; взаимодействие частей — схема последовательности; «до и после»
— вывод теста или снимок экрана. Оставляй только то, что нужно для текущего вопроса.
